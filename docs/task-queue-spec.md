# Task Queue System — Implementation Spec

**Type:** Implementation
**Status:** Draft
**Stack:** Temporal (self-hosted), Bun + TypeScript (worker + submitter), NATS (result fanout)

---

## 1. Overview

A Temporal-based task queue that dispatches Claude Code CLI invocations to capable workers. Workers register on task queues matching their role (e.g. `homekube-worker`). Results are stored in Temporal (queryable by workflow ID) and published to NATS for fanout.

### Components

| Component | Language | Responsibility |
|-----------|----------|----------------|
| Temporal Server | Docker/k8s | Workflow orchestration, persistence, task queue routing |
| Worker | Bun + TypeScript | Polls Temporal task queue, runs `claude` CLI, reports result |
| Submitter Library | Bun + TypeScript | Enqueues tasks via Temporal client, returns workflow ID |
| Result Publisher | Part of workflow | On completion, publishes result to NATS stream |

### Architecture Diagram

```
                        ┌──────────────┐
  Submitter ──────────► │   Temporal   │
  (enqueue task         │   Server     │
   with role)           └──────┬───────┘
                               │ task queue: "homekube-worker"
                    ┌──────────┼──────────┐
                    ▼          ▼          ▼
               Worker-1   Worker-2   Worker-3
               (claude)   (claude)   (claude)
                    │          │          │
                    └──────────┼──────────┘
                               │ workflow result
                               ▼
                        ┌──────────────┐
                        │  NATS Stream │  ── fanout to consumers
                        │  task.results│
                        └──────────────┘
```

## 2. Data Model

### Task Input

```typescript
interface TaskInput {
  /** Unique task ID (UUID, generated by submitter) */
  taskId: string;
  /** The prompt to send to Claude Code */
  prompt: string;
  /** Working directory for Claude Code (absolute path on worker) */
  workDir: string;
  /** Optional: max time in seconds for Claude Code execution. Default: 300 */
  timeoutSeconds?: number;
  /** Optional: additional CLI flags passed to claude */
  extraFlags?: string[];
  /** Optional: metadata for result consumers */
  metadata?: Record<string, string>;
}
```

### Task Result

```typescript
interface TaskResult {
  taskId: string;
  /** Workflow ID in Temporal (for querying) */
  workflowId: string;
  status: "completed" | "failed" | "timed_out";
  /** Claude Code JSON output (stdout parsed) */
  output?: string;
  /** stderr if failed */
  error?: string;
  /** Wall-clock duration in milliseconds */
  durationMs: number;
  /** Which worker handled it */
  workerId: string;
  /** ISO 8601 timestamp */
  completedAt: string;
}
```

## 3. Temporal Configuration

### Namespace

- Name: `task-queue`
- Retention: 7 days (workflow history)

### Workflow

- **Name:** `claude-task`
- **ID pattern:** `task-{taskId}` (enables dedup — resubmitting same taskId is idempotent)
- **Task queue:** Determined by submitter based on required role (e.g. `homekube-worker`)
- **Execution timeout:** `taskInput.timeoutSeconds + 60s` (grace period for process cleanup)
- **Run timeout:** Same as execution timeout (single-run, no continue-as-new)

### Activity

- **Name:** `run-claude`
- **Start-to-close timeout:** `taskInput.timeoutSeconds` (default 300s)
- **Heartbeat timeout:** 30s (worker must heartbeat during long runs)
- **Retry policy:**
  - Max attempts: 3
  - Initial interval: 5s
  - Backoff coefficient: 2.0
  - Non-retryable errors: `NonRetryableError` (task itself failed, not infra)

### Result Publishing Activity

- **Name:** `publish-result`
- **Start-to-close timeout:** 10s
- **Retry policy:** Max attempts 5, initial interval 1s
- **Task queue:** Same as the workflow (worker publishes)

## 4. Worker Implementation

### Process Lifecycle

```
Worker start:
  1. Connect to Temporal (TEMPORAL_ADDRESS env var)
  2. Connect to NATS (NATS_URL env var)
  3. Register activities: run-claude, publish-result
  4. Start polling task queue (TASK_QUEUE env var, e.g. "homekube-worker")
  5. Log: "Worker {workerId} polling {taskQueue}"

Worker stop (SIGINT/SIGTERM):
  1. Stop polling (graceful shutdown)
  2. Wait for in-flight activity to complete (up to 30s)
  3. Disconnect Temporal + NATS
  4. Exit 0
```

### run-claude Activity

```
Input: TaskInput
Output: TaskResult

1. Validate workDir exists, reject with NonRetryableError if not
2. Build command:
   claude --dangerously-skip-permissions \
     -p "{prompt}" \
     --output-format json \
     {extraFlags...}
3. Spawn child process in workDir
4. Start heartbeat loop (every 10s, report to Temporal)
5. Collect stdout + stderr
6. On process exit:
   - Exit 0 → status "completed", parse stdout as output
   - Exit non-zero → status "failed", stderr as error
7. On timeout (Temporal cancellation):
   - SIGTERM child process
   - Wait 5s, SIGKILL if still alive
   - Return status "timed_out"
8. Return TaskResult
```

### publish-result Activity

```
Input: TaskResult
Output: void

1. Publish to NATS JetStream subject: task.results.{taskId}
2. Payload: JSON-serialized TaskResult
3. Wait for ack from JetStream
```

### Worker ID

- Format: `{hostname}-{pid}` (e.g. `homekube-worker-0-12345`)
- Set at startup, constant for process lifetime

## 5. Submitter Library

### API

```typescript
class TaskSubmitter {
  constructor(temporalAddress: string);

  /**
   * Enqueue a task. Returns workflow ID for tracking.
   * taskQueue = the role/capability queue to target.
   */
  async submit(taskQueue: string, input: TaskInput): Promise<string>;

  /**
   * Get result of a completed task. Throws if not yet complete.
   */
  async getResult(workflowId: string): Promise<TaskResult>;

  /**
   * Wait for task to complete and return result.
   * Blocks until workflow finishes or timeout.
   */
  async waitForResult(workflowId: string, timeoutMs?: number): Promise<TaskResult>;
}
```

### Workflow ID Generation

- Pattern: `task-{taskId}`
- Resubmitting the same `taskId` returns the existing workflow (Temporal dedup)

### Task Queue Naming Convention

- Format: `worker.{machine-name}` (e.g. `worker.windows`, `worker.nas`)
- Each remote machine runs one worker binary targeting its own queue
- To send a task to a specific machine, submit to its queue name

## 6. NATS Result Stream

### Stream Configuration

- **Stream name:** `TASK_RESULTS`
- **Subjects:** `task.results.>`
- **Storage:** File
- **Retention:** Limits-based, 10,000 messages or 7 days (whichever first)
- **Discard policy:** Old

Workers create the stream on startup if it doesn't exist (idempotent).

### Temporal Server

Use the official `temporalio/helm-charts` Helm chart with PostgreSQL persistence via CNPG.

| Resource | Details |
|----------|---------|
| Namespace | `temporal` |
| Helm chart | `temporalio/temporal` |
| Database | CNPG PostgreSQL cluster `temporal-db` in `temporal` namespace |
| Services | frontend (7233), history, matching, worker (internal Temporal workers) |
| Visibility store | Same PostgreSQL (standard visibility, not advanced) |

### Worker Deployment

| Field | Value |
|-------|-------|
| Namespace | `default` |
| Deployment name | `task-worker` |
| Image | Built from `task-worker/Dockerfile` |
| Replicas | 1 (scale as needed) |
| Env: `TEMPORAL_ADDRESS` | `temporal-frontend.temporal:7233` |
| Env: `NATS_URL` | `nats://nats.nats:4222` |
| Env: `TASK_QUEUE` | `homekube-worker` |
| Resource limits | cpu: 2, memory: 4Gi (Claude Code is heavy) |

### Remote Worker (Single Binary)

Workers are distributed as Bun-compiled single executables to remote machines.

| Field | Value |
|-------|-------|
| Build command | `bun build --compile --target=bun-{platform} src/worker.ts --outfile task-worker` |
| Targets | `bun-linux-x64`, `bun-windows-x64` (add as needed) |
| Config | Environment variables or `.env` file alongside binary |
| Env: `TEMPORAL_ADDRESS` | Temporal frontend (must be network-reachable from remote machine) |
| Env: `NATS_URL` | NATS server (must be network-reachable from remote machine) |
| Env: `TASK_QUEUE` | `worker.windows`, `worker.nas`, etc. |
| Env: `WORK_DIR` | Local working directory on the remote machine |
| Concurrency | 1 (single Claude Code execution at a time) |

## 9. Anti-Patterns (DO NOT)

| ❌ Don't | ✅ Do Instead | Why |
|----------|---------------|-----|
| Run multiple Claude processes concurrently per worker | One activity at a time per worker (Temporal `maxConcurrentActivityTaskExecutions: 1`) | Claude Code is resource-heavy, concurrent runs degrade both |
| Store results only in Temporal | Publish to NATS as well | Temporal queries are for the submitter; NATS fanout is for other consumers |
| Use Temporal signals/queries for result notification | Use NATS pub/sub for fanout | Temporal is not a message broker; NATS is |
| Hardcode task queue names in worker | Use TASK_QUEUE env var | Same image can serve different roles |
| Retry tasks that Claude intentionally rejected | Mark as NonRetryableError when exit code indicates prompt refusal | Retrying won't change Claude's mind |
| Skip heartbeats during long Claude runs | Heartbeat every 10s | Temporal assumes worker is dead after heartbeat timeout, reassigns task |
| Parse Claude output as plain text | Use `--output-format json` and parse JSON | Structured output is reliable; text output format changes between versions |

## 11. Error Handling Matrix

| Error Type | Detection | Response | Retry? | Logging |
|------------|-----------|----------|--------|---------|
| Claude process exit non-zero | Process exit code ≠ 0 | Return status "failed" with stderr | Yes (up to 3x) | WARN |
| Claude process OOM killed | Exit code 137 | Return status "failed" | Yes (up to 3x) | ERROR |
| Claude permission/refusal | Exit code + stderr contains refusal | NonRetryableError | No | WARN |
| workDir doesn't exist | fs.stat check | NonRetryableError | No | ERROR |
| Temporal connection lost | SDK throws | Worker process crashes, k8s restarts | N/A (infra) | ERROR |
| NATS connection lost | publish-result fails | Activity retries (5x) | Yes | ERROR |
| Heartbeat timeout | Temporal detects no heartbeat | Temporal reassigns activity to another worker | Yes (new worker) | WARN (on Temporal side) |
| Child process won't die | SIGTERM timeout (5s) | SIGKILL | N/A | ERROR |
